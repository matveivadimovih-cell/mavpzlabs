# ADR 0001 Збереження історії видач через асоціативну сутність
## Контекст і постановка проблеми
Для роботи системи бібліотеки треба відстежувати поточний статус конкретного примірника. Постає питання, чи треба зберігати повну історію видач примірників чи достатньо знати лише поточний стан кожного примірника.
## Розглянуті варіанти
- Варіант 1:
Залишити прямий зв'язок між сутностями Читач та Примірник, додати додатковий атрибут сутності Примірник для відстеження поточного статусу, що перезаписується при кожній зміні.
- Варіант 2:
Створити окрему асоціативну сутність Видача з додатковмим атрибутами часу, прострочення та статусу повернення.
## Переваги й недоліки
- Варіант 1:
Плюси:
Простий у реалізації, модель не ускладнюється.
Мінуси: Повністю втрачається історія користування примірниками, дати повернення, неможливо ідентифікувати, у якого читача примірник був місяць тому.
- Варіант 2:
Плюси: Зберігається історія та хронологія користування примірниками. Дозволяє фіксувати дати повернення, строки видачі та завершення видачі, минулих користувальників.
Мінуси: Ускладнення моделі, створення додаткової сутності, зв'язків.
## Результат рішення
Обрано варіант 2 (асоціативна сутність), оскільки для бібліотеки важливо збирати статистику користування задля аудиту популярності, стану примірників.
## Наслідки
Позитивні:
Система зберігає повну хронологію користування примірниками та дозволяє генерувати аналітику.
Мінуси:
Модель ускладнилася, була утворена додаткова сутність, що потребує валідації, додаткових обмежень у spec.md.
